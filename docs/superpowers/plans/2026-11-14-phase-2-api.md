# Phase 2: Prediction API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the Phase 1 models through a public FastAPI service: given the signing-time attributes of a (real or hypothetical) contract and its buyer, return calibrated probabilities of a value addition and a time extension, their percentile against recent contracts, and the top signals behind each score.

**Architecture:** An offline `export-bundle` step packages both calibrated models, a buyer table with point-in-time history as of the export date, and metadata (global rates, metrics, score quantiles) into a small directory. The API loads that bundle at startup and scores requests with the **same DuckDB feature SQL** used for training, which avoids train/serve skew. A Docker image (port 7860) runs on a Hugging Face Space. The bundle is published as a GitHub Release asset, and a manual GitHub Actions workflow deploys the code plus the bundle to the Space.

**Tech Stack:** FastAPI, Pydantic v2, Uvicorn, DuckDB, LightGBM, Docker, GitHub Actions, `huggingface_hub`.

**Spec:** `docs/superpowers/specs/2026-11-14-procurement-risk-design.md` (§7 architecture, §8 Phase 2, §11 "Serving contract": `/predict` scores a hypothetical contract from signing-time attributes plus an entity code; the entity's history comes from a compact table built by the pipeline and bundled at deploy time).

## Global Constraints

- English everywhere. Every prediction response carries the disclaimer "Scores are statistical estimates for analysis, not allegations of wrongdoing." Never the words "corruption" or "fraud".
- Free hosting only: GitHub Releases for the bundle, a Hugging Face Space (Docker SDK, CPU basic) for the API.
- **No supplier identifiers anywhere in the bundle or the API.** Supplier history is not served: requests are scored with `supplier_prior_n = 0` and the training-period global rates, which is a state the model saw for most training rows (about 86% of contracts are with natural persons, most with no prior history). This is documented in the API docs.
- The buyer table holds public entity fields only: `buyer_id, buyer_name, buyer_department, buyer_city, buyer_order, buyer_sector, buyer_branch, buyer_centralized` plus history.
- **Feature parity:** serving features come from the same SQL as training features. Any feature logic lives in one place.
- Container listens on port 7860, runs as a non-root user, and starts with no network access to SECOP.
- CORS origins come from env `ALLOWED_ORIGINS` (comma-separated, default `*` for the public demo).
- Publishing (GitHub Release, Hugging Face Space) is outward-facing: ask the owner in chat before each one. The owner creates the Hugging Face account, Space and token themselves. Tokens never pass through chat.

## Review Focus

1. Train/serve skew: a contract scored through the API gets different features than the same contract in the training dataset. Expected: identical features. Test in Task 3.
2. Optional fields missing (no budget, no bidders, no planned start): the response is still 200 with null-driven features, never a 500. Test in Task 4.
3. Unknown `buyer_id` returns 404 with a hint to use `/buyers`. An unseen categorical value (new procurement method) is scored, with a `warnings` entry. Tests in Task 4.
4. Bundle/code mismatch: the bundle's feature list differs from `CATEGORICAL_FEATURES + NUMERIC_FEATURES`. Expected: the API refuses to start with a clear error. Test in Task 2.
5. Out-of-range input (negative values, a duration over 3,650 days, a start date before 2000, more than 50 contracts in a batch) returns 422, not a silent clip. Test in Task 4.

### Task 2: Serving bundle

**Files:**
- Create: `src/procurement_risk/serving/__init__.py`, `src/procurement_risk/serving/bundle.py`, `tests/serving/__init__.py`, `tests/serving/test_bundle.py`
- Modify: `src/procurement_risk/__main__.py` (command `export-bundle`), `.gitignore` (`serving_bundle/`)

**Interfaces:**
- Consumes: `open_audit_db`, `build_canonical`, `build_labels`, `build_history`, `feature_frame`, `RiskModel`, `data/models/<target>/{model.joblib,metrics.json}`, the dataset parquet (for test-period score quantiles).
- Produces:
  - Bundle layout: `<dir>/models/has_value_addition.joblib`, `<dir>/models/has_time_extension.joblib`, `<dir>/buyers.parquet`, `<dir>/metadata.json`.
  - `buyers.parquet` columns: `buyer_id, buyer_name, buyer_department, buyer_city, buyer_order, buyer_sector, buyer_branch, buyer_centralized, buyer_prior_n, buyer_prior_value_addition_rate, buyer_prior_extension_rate`. History is computed **as of the export date**: a synthetic contract per buyer with `signed_at = as_of` goes through `build_history`. Attributes come from each buyer's most recent contract. `buyer_name` is `nombre_entidad`, read from the raw contracts.
  - `metadata.json`: `{"bundle_version": "YYYY-MM-DD", "as_of", "features": [...], "categorical_features": [...], "global_rates": {...}, "metrics": {target: {model: metrics}}, "score_quantiles": {target: [101 floats]}, "disclaimer": DISCLAIMER}`. Quantiles are of calibrated test-period probabilities.
  - `export_bundle(raw_dir: Path, dataset_path: Path, models_dir: Path, out_dir: Path, as_of: date) -> Path`
  - `@dataclass Bundle(models: dict[str, RiskModel], buyers: pandas.DataFrame, metadata: dict)` and `load_bundle(path: Path) -> Bundle`. `load_bundle` raises `BundleError` when `metadata["features"] != list(CATEGORICAL_FEATURES + NUMERIC_FEATURES)` or a model file is missing (Review Focus 4).
  - `make_demo_bundle(out_dir: Path, seed: int = 0) -> Path`: a tiny bundle trained on synthetic data (about 3,000 rows, 3 buyers named "Demo buyer A/B/C") for tests and the CI Docker smoke test.
  - CLI: `python -m procurement_risk export-bundle --raw data/raw --dataset data/processed/dataset.parquet --models data/models --out serving_bundle --as-of 2026-11-14`, and `python -m procurement_risk demo-bundle --out serving_bundle`.

### Task 3: Scoring with feature parity

**Files:**
- Create: `src/procurement_risk/serving/scoring.py`, `src/procurement_risk/serving/labels.py`, `tests/serving/test_scoring.py`
- Modify: `src/procurement_risk/model/explain.py` (vectorised `top_signals`)

**Interfaces:**
- Consumes: `Bundle`, `FEATURE_SELECT`/`feature_frame`, `explain.contributions`.
- Produces:
  - `scoring.score(bundle: Bundle, contracts: list[dict]) -> list[dict]`. Each input dict uses canonical names: `buyer_id`, `signed_at`, `planned_start_at`, `procurement_method`, `contract_type`, `category_code`, `funding_source`, `award_value`, `tender_budget`, `planned_duration_days`, `tender_published_at`, `n_bidders`, `n_responses`, `n_invited`, `n_lots`, `supplier_is_natural_person`, `supplier_is_sme`, `supplier_is_group`, `advance_payment_enabled`, `extendable_clause`.
    - Steps: buyer attributes and history come from `bundle.buyers`. A temporary `canonical_contracts` table is built, plus `history_buyer` from the bundle and `history_supplier` with `n = 0` and global rates. The features then come from `feature_frame(con, closed_only=False)`.
    - Output per contract: `{"value_addition": {...}, "time_extension": {...}, "warnings": [...]}`. Each target holds `probability`, `percentile` (0–100 against `score_quantiles`) and `top_signals`: up to 3 `{"feature", "label", "contribution"}` entries with positive SHAP contribution.
    - Warnings: `"unseen value for <feature>: <value>"` when a categorical value is not in the model vocabulary.
  - `scoring.UnknownBuyerError(KeyError)`.
  - `labels.FEATURE_LABELS: dict[str, str]`, a human-readable English name for every feature (for example `"buyer_prior_value_addition_rate": "Buyer's past value-addition rate"`). A test asserts every feature has a label.
  - `explain.top_signals`, vectorised with numpy (no `iterrows`). Same signature and output as before.

### Task 4: FastAPI app

**Files:**
- Create: `src/procurement_risk/api/__init__.py`, `src/procurement_risk/api/schemas.py`, `src/procurement_risk/api/app.py`, `tests/api/__init__.py`, `tests/api/test_app.py`
- Modify: `pyproject.toml`:
  - Base dependencies become `duckdb, pyarrow, pandas, numpy, scikit-learn, lightgbm, joblib, httpx`.
  - New optional extras `train = ["mlflow", "matplotlib"]` and `api = ["fastapi", "uvicorn[standard]"]`.
  - Dev group adds `fastapi` test client deps.
  - `.github/workflows/ci.yml` uses `uv sync --all-extras`.

**Interfaces:**
- Consumes: `load_bundle`, `score`, `UnknownBuyerError`.
- Produces `create_app(bundle_dir: Path | None = None) -> FastAPI`. `bundle_dir` defaults to env `BUNDLE_DIR` or `serving_bundle`. Endpoints:
  - `GET /health` → `{"status": "ok", "bundle_version": ...}`.
  - `GET /metadata` → bundle version, as-of, test metrics, feature labels, disclaimer.
  - `GET /buyers?q=<text>&limit=20` → case- and accent-insensitive substring search on `buyer_name`, returning `buyer_id, buyer_name, buyer_department, buyer_city`. `limit` ≤ 100.
  - `POST /predict`:
    - Body `PredictRequest {contracts: list[ContractIn]}` with 1–50 contracts.
    - Response `PredictResponse {bundle_version, disclaimer, results: list[ContractScore]}`.
    - Unknown buyer → 404 `{"detail": "unknown buyer_id '<id>'; search /buyers?q=..."}`.
  - `ContractIn` field constraints (Review Focus 5):
    - `buyer_id: str` (required).
    - `signed_at: date` (default today, ≥ 2000-01-01).
    - `planned_start_at, tender_published_at: date | None`.
    - Categorical strings optional.
    - `category_code` matches `^V1\.\d{8}$` or is null.
    - `award_value, tender_budget: float | None` (≥ 0).
    - `planned_duration_days: float | None` (> 0, ≤ 3650).
    - `n_*: int | None` (≥ 0).
    - Booleans optional.
  - Example request in the OpenAPI schema (`model_config` `json_schema_extra`).
  - CORS middleware from `ALLOWED_ORIGINS`.
  - `/docs` is enabled. The title is "Procurement Risk Radar API" and the description includes the disclaimer and the supplier-history note.
